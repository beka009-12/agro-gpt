# Геолокация в чате + предупреждение при отказе — дизайн

Дата: 2026-07-17. Ветка: `feat/v4-redesign`. Бэкенд: `POST /diagnosis/` уже принимает опциональные `latitude`/`longitude` (multipart, nullable) — см. `openapi.json`.

## Цель

1. При первой отправке сообщения в чате запрашивать у браузера геолокацию и передавать координаты с каждым сообщением в `/diagnosis/` (бэк учитывает погоду района в рекомендациях).
2. Если пользователь отклонил доступ — показывать вверху чата заметное полукрасное предупреждение о том, что без геолокации диагностика может быть менее точной.

## Решение (подход A — хук + баннер в ChatView)

Небольшой клиентский хук с геосостоянием, баннер-компонент над списком сообщений, координаты подмешиваются в существующий `send()`. Профиль уже загружается в `ChatShell` — признак сохранённой локации пробрасывается пропом. Альтернативы (гео-контекст на уровне `ChatShell`; всё инлайном в `ChatView`) отклонены: первое — YAGNI, второе раздувает `chat-view.tsx`.

## Компоненты

### 1. Хук `src/components/chat/use-chat-geo.ts`

Клиентский хук, единственный владелец геосостояния чата.

- Состояние: `"idle" | "granted" | "denied" | "unavailable"`; координаты `{ latitude: number; longitude: number } | null` в `ref` (не вызывают ререндер).
- **На маунте** — тихая проверка `navigator.permissions.query({ name: "geolocation" })` в `try/catch` (Safari < 16 не поддерживает — тогда остаёмся в `idle`):
  - `denied` → сразу состояние `denied` (баннер виден до первого сообщения);
  - `granted` → состояние `granted`, координаты получим при отправке;
  - `prompt` → `idle`, браузерный запрос появится при первой отправке.
- **`getCoords(): Promise<Coords | null>`** — вызывается из `send()` перед каждой отправкой:
  - координаты уже в `ref` → вернуть их сразу;
  - состояние `denied`/`unavailable` → вернуть `null` без запроса;
  - иначе `navigator.geolocation.getCurrentPosition` с `timeout: 8000`, `maximumAge: 5 * 60 * 1000`; успех → закэшировать в `ref`, состояние `granted`; `PERMISSION_DENIED` → `denied`; таймаут/ошибка позиции → `unavailable`; всегда вернуть результат (или `null`), **не** бросать — отправка сообщения не блокируется и не ломается.
  - `!("geolocation" in navigator)` → `unavailable`.
- Параллельные вызовы `getCoords` (двойной сабмит) переиспользуют один in-flight промис.

### 2. Баннер `src/components/chat/geo-warning-banner.tsx`

- Полоса вверху чата: рендерится в `ChatView` над `MessageList`, внутри колонки `max-w-[800px]`.
- Вид: полукрасный — `bg-destructive/10`, `border border-destructive/30`, текст тёмно-красным (`text-destructive`), слева иконка предупреждения (треугольник, добавить в `src/components/ui/icons.tsx` по образцу существующих), справа крестик закрытия с aria-label.
- `role="alert"` для screen reader.
- Появление — плавное (motion-токены проекта `DURATION`/`EASE_OUT`), с учётом `useReducedMotion` как в остальном UI.
- Закрытие: крестик пишет флаг в `sessionStorage` (`ibo_geo_banner_dismissed=1`) — скрыт до конца сессии вкладки, при новом заходе появится снова, если разрешения так и нет. Чтение/запись `sessionStorage` в `try/catch` (privacy-режимы).

### 3. Условия показа баннера

Показывается только когда **все** условия истинны:

- состояние гео строго `denied` (реальный отказ пользователя). `unavailable` (нет API, таймаут при разрешённом доступе) баннер **не** вызывает — его текст про запрет доступа и был бы ложным;
- в профиле нет сохранённой локации: `!(profile.location_available || (profile.latitude !== null && profile.longitude !== null))` — логика та же, что `hasLocation` в `profile-menu.tsx`;
- не закрыт в этой сессии (`sessionStorage`).

`ChatShell` передаёт в `ChatView` проп `hasProfileLocation: boolean` (профиль там уже есть через `useProfile`). Пока профиль ещё грузится (`profile === null`) считаем `hasProfileLocation = false` — при отказе баннер может мигнуть и скрыться после загрузки профиля с локацией; допустимо, состояние редкое.

### 4. Интеграция в `chat-view.tsx`

В `send()`: перед сборкой `FormData` — `const coords = await getCoords()`; при наличии добавить `form.set("latitude", String(coords.latitude))` и `form.set("longitude", String(coords.longitude))`. Первая отправка при состоянии `prompt` ждёт ответа на браузерный запрос, но не дольше 8 сек таймаута — потом сообщение уходит без координат.

### 5. Прокси-роут `app/api/chat/message/route.ts`

- Новая zod-схема в `src/lib/chat-schemas.ts`: `latitude: z.coerce.number().min(-90).max(90)`, `longitude: z.coerce.number().min(-180).max(180)` (пара, обе обязательны внутри схемы).
- Из формы читаются `latitude`/`longitude`; если оба присутствуют и валидны — пробрасываются в `backendForm` для `/diagnosis/`; иначе молча отбрасываются (сообщение не ломаем, 400 не отдаём — координаты опциональны).

### 6. i18n

В `src/i18n/{ru,en,ky}.json` новый блок `chat.geoWarning`:

- `text` — RU: «Вы не разрешили доступ к местоположению — диагностика может быть менее точной: без него мы не учитываем погоду вашего района.»
- `dismissLabel` — RU: «Скрыть предупреждение».

EN/KY — переводы по образцу; KY — мой перевод, требует вычитки носителем (как ранее).

## Ошибки и крайние случаи

- Отказ/таймаут/недоступность гео **никогда** не блокируют отправку сообщения — координаты просто не прикладываются.
- Safari без `navigator.permissions` → баннер появится только после реального отказа при первой отправке.
- Браузер без геолокации или таймаут позиции при разрешённом доступе → состояние `unavailable`, координат нет, баннера нет.
- Невалидные координаты в прокси-роуте отбрасываются молча.
- `sessionStorage` недоступен → баннер просто нельзя «запомнить» закрытым в рамках сессии (закрывается в state до ремаунта).
- «Новый чат» (`key={sessionId}` ремаунтит `ChatView`) не сбрасывает закрытие баннера — флаг в `sessionStorage`, хук и баннер читают его заново.

## Тестирование

- `tsc`, `lint`, `build` — чисто.
- Smoke: `/chat` 307 без токена; `POST /api/chat/message` без токена → 401; с невалидными координатами → сообщение проходит, координаты не пробрасываются.
- Ручная проверка в браузере (за пользователем): разрешить → координаты уходят в `/diagnosis/`; отклонить → красный баннер вверху чата; закрыть баннер → не возвращается до новой вкладки; сохранённая локация в профиле → баннера нет при отказе.

## Вне скоупа

- Изменение логики локации в профиль-меню (остаётся как есть).
- Сохранение координат из чата в профиль (`PATCH /api/profile/location` из чата не зовём).
- Обратное гео-кодирование, отображение координат пользователю в чате.
